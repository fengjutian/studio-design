# 人人都是电影导演：产品定义与 MVP 规格

> 文档状态：Draft v0.1  
> 产品形态：桌面端 AI 电影创作工作站  
> 技术载体：Tauri  
> 首期视频引擎：MiniMax  
> 核心体验：Idea → Movie

## 1. 产品定义

### 1.1 一句话定位

**让不会写 Prompt、不会摄影、不会剪辑的人，也能像导演一样完成一部电影。**

“人人都是电影导演”不是传播口号，而是产品的核心定义。产品不要求用户学习 AI 工具，而是让 AI 理解、补全并执行用户的导演意图。

### 1.2 产品承诺

- 人人都是导演。
- 你负责想象，AI 负责执行。
- 一句话，可以成为一个镜头。
- 一个想法，可以成为一部电影。

### 1.3 产品不是什么

本产品不是 Prompt 编辑器、模型参数面板、API 调试工具，也不只是“文生视频”。

```text
文生视频：文本 → 视频片段

本产品：想法 → 故事 → 场景 → 镜头 → 素材 → 剪辑 → 电影
```

底层生成模型是制作能力，不是产品主体。用户创作的是电影，而不是一次模型调用。

## 2. 用户与价值

### 2.1 目标用户

**首要用户：零基础创作者**

- 有故事或画面想法，但不会写 Prompt。
- 不理解镜头、灯光、焦段、运镜等专业术语。
- 希望快速得到结构完整、可以观看和分享的短片。

**次要用户：内容创作者**

- 需要制作短视频、概念片、MV、广告样片或故事预演。
- 重视创作效率、风格一致性和镜头可修改性。

**进阶用户：影视与 AI 视频从业者**

- 需要逐镜头控制创作意图和生成参数。
- 希望保留 Prompt、模型、Seed、参考素材等高级能力。

### 2.2 核心用户任务

当用户有一个模糊的故事、场景或画面时，他可以用自然语言讲出来，由 AI 将其发展成可确认、可修改、可生成、可剪辑的电影项目。

### 2.3 产品价值

| 用户障碍 | 产品响应 |
| --- | --- |
| 不知道如何把想法写成剧本 | AI 编剧整理故事与情节 |
| 不知道需要哪些镜头 | AI 导演拆解场景和分镜 |
| 不懂摄影语言 | AI 摄影指导自动选择景别、机位和运镜 |
| 难以保持人物与风格一致 | 角色、场景和视觉参考作为项目资产复用 |
| 不会剪辑 | AI 按叙事顺序组织素材并形成时间线 |
| 不会写 Prompt | 普通模式隐藏 Prompt，由导演意图驱动生成 |

## 3. 核心设计原则

### 3.1 导演意图优先

界面首先接收“我想表达什么”，而不是“模型需要什么参数”。专业术语由 AI 在幕后补全。

例如用户输入：

> 让这个镜头更有压迫感。

系统可以在内部解释为低机位、广角、低照度、高反差、缓慢推进和更强环境音，但普通模式不强迫用户理解这些设置。

### 3.2 Prompt 默认不可见

普通用户看到的是故事、场景、角色、镜头和创作建议。Prompt、Negative Prompt、Seed、模型参数只在导演模式中出现。

### 3.3 AI 提案，人做决定

AI 可以主动拆解、补全和推荐，但关键创作节点必须让用户确认。建议统一提供三种动作：

- 接受：采用当前方案并进入下一阶段。
- 修改：用自然语言或表单调整局部内容。
- 重新设计：保留原始意图，生成另一套完整方案。

### 3.4 先成片，再精修

默认流程应尽快形成可播放的粗剪版本，然后允许用户按场景或镜头逐步优化。不要要求用户在第一次生成前完成所有专业设置。

### 3.5 模型与供应商解耦

MiniMax 是首个视频 Provider，不应进入核心产品概念和项目数据模型。未来可接入 Kling、Veo、Runway、其他云端或本地模型。

## 4. 核心体验

### 4.1 首页

首页不是项目管理后台或 API 控制台，而是创作的起点。

```text
┌──────────────────────────────────────────────┐
│                                              │
│             人人都是电影导演                 │
│                                              │
│       今天，你想拍一部什么电影？             │
│                                              │
│   ┌──────────────────────────────────────┐   │
│   │ 一个下着暴雨的夜晚，一个年轻人……     │   │
│   └──────────────────────────────────────┘   │
│                                              │
│              [ 开始创作电影 ]                │
│                                              │
│          最近创作                            │
│          《雨夜》  制作中                    │
└──────────────────────────────────────────────┘
```

首要操作固定为“开始创作电影”，最近项目是次要入口。

### 4.2 从想法到电影

```text
表达想法
   ↓
AI 理解并复述创作意图
   ↓
生成故事提案
   ↓
拆分场景与镜头
   ↓
用户接受 / 修改 / 重新设计
   ↓
生成镜头素材
   ↓
自动进入时间线并形成粗剪
   ↓
逐镜头调整或重新生成
   ↓
预览与导出电影
```

### 4.3 示例交互

用户：

> 我想拍一个少年在雨夜的上海街头奔跑，最后停在一家便利店门口。

AI 导演：

> 我理解这是一个紧张、孤独的雨夜追逐场景，故事最后在明亮的便利店门口获得短暂喘息。我建议用 5 个镜头、约 20 秒来表现。

```text
Scene 01  雨夜街头

Shot 01   城市远景，建立雨夜上海
Shot 02   少年在街头奔跑
Shot 03   鞋踩过积水的特写
Shot 04   贴近人物的侧后方跟拍
Shot 05   少年停在便利店门口

[接受方案] [修改方案] [重新设计]
```

## 5. 信息架构

### 5.1 一级结构

```text
首页
├── 开始创作电影
├── 最近创作
└── 我的电影

电影工作台
├── AI 导演
├── 故事
├── 场景
├── 镜头
├── 素材
├── 时间线
└── 导出

全局设置
├── 生成服务
├── 存储与缓存
├── 默认画幅与清晰度
└── 关于
```

### 5.2 电影工作台布局

建议采用稳定的三栏加时间线结构：

```text
┌────────────┬─────────────────────────┬──────────────┐
│ 项目结构   │       画布 / 预览       │ AI 导演      │
│ Story      │                         │ 对话与建议    │
│ Scene      │                         │ 接受 / 修改   │
│ Shot       │                         │ 重新设计      │
├────────────┴─────────────────────────┴──────────────┤
│                    Timeline                         │
└─────────────────────────────────────────────────────┘
```

- 左侧回答“电影由什么组成”。
- 中间回答“当前正在看和编辑什么”。
- 右侧回答“我想让 AI 怎么改”。
- 底部回答“整部电影如何随时间播放”。

## 6. 核心对象模型

### 6.1 对象关系

```text
Movie
├── Story
├── Characters
├── Visual Style
├── Scenes[]
│   └── Shots[]
│       ├── Shot Specification
│       ├── Generations[]
│       └── Selected Asset
└── Timeline
    └── Clips[]
```

### 6.2 Movie

一部可持续编辑和最终导出的电影项目。

关键字段：标题、创作意图、故事梗概、状态、画幅、目标时长、视觉风格、创建时间、更新时间。

建议状态：

```text
构思中 → 设计中 → 生成中 → 剪辑中 → 已完成
```

### 6.3 Scene

叙事上的连续时空单元，是组织镜头的上层结构。

关键字段：序号、标题、地点、时间、情绪、场景描述、出场角色、镜头列表。

### 6.4 Shot

最小导演与生成单元。用户对镜头提出修改，生成服务也以镜头为主要输入。

关键字段：序号、叙事目的、主体与动作、景别、构图、机位、运镜、镜头时长、灯光、声音、参考素材、生成状态。

### 6.5 Shot Specification

Director Engine 产生的供应商无关镜头规格。它既能被普通语言编辑，也能被不同 Provider 转换为各自的生成参数。

```text
用户意图
   ↓
Director Engine
   ↓
Shot Specification
   ├── narrative
   ├── subject
   ├── action
   ├── environment
   ├── camera
   ├── lighting
   ├── visualStyle
   ├── audioIntent
   └── constraints
   ↓
Provider Adapter
   ↓
模型请求
```

### 6.6 Generation

一次生成尝试，不等同于镜头。一个 Shot 可以拥有多个 Generation，用户从中选择一个版本进入时间线。

关键字段：所属镜头、Provider、模型、请求快照、状态、进度、输出资产、错误信息、创建时间。

建议状态：

```text
等待中 → 提交中 → 生成中 → 成功
                     └→ 失败 / 已取消
```

### 6.7 Asset 与 Timeline

Asset 是生成或导入的图片、视频、音频和参考素材。Timeline 通过 Clip 引用 Asset，不直接拥有媒体文件，从而支持换版本、重排和重复使用。

## 7. 两层创作模式

### 7.1 普通模式（默认）

用户通过自然语言和少量直观选项完成创作：

- 想拍什么。
- 想要什么感觉。
- 想修改哪里。
- 是否接受 AI 提案。

普通模式不展示 Prompt、Seed、采样参数和供应商字段。

### 7.2 导演模式

为专业用户提供逐镜头精细控制：

```text
Scene
Shot
Camera
Lens
Motion
Lighting
Composition
Reference
Prompt
Negative Prompt
Seed
Model
```

两个模式操作同一份 Shot Specification。切换模式不能丢失内容，也不能建立两套互不兼容的数据。

## 8. AI Director 与 Provider 架构

### 8.1 AI 的角色

用户始终是导演。AI 是一组协同工作的幕后能力：

- 编剧：整理故事、人物和情节。
- 副导演：拆解场景、规划制作顺序。
- 摄影指导：设计景别、机位、镜头和运镜。
- 美术与灯光：补全环境、色彩、材质与光线。
- 演员与动作指导：保持角色并描述表演。
- 剪辑与声音设计：组织节奏、转场、对白和环境音。

对用户而言，这些能力统一表现为“AI 导演助手”，避免引入多个机器人或复杂工作流。

### 8.2 分层架构

```text
用户界面
   ↓
Director Engine
   ↓
Story / Scene / Shot Specification
   ↓
Generation Orchestrator
   ↓
Provider Adapter
   ├── MiniMax（首期）
   ├── Kling（未来）
   ├── Veo（未来）
   ├── Runway（未来）
   └── Local（未来）
   ↓
Video Assets
   ↓
Timeline / Export
```

### 8.3 MiniMax 首期定位

MiniMax 只负责模型能力适配，包括鉴权、请求转换、任务提交、状态轮询、结果下载和错误归一化。

业务层不应直接依赖 MiniMax 的字段命名；项目文件也不应只存储 MiniMax Prompt。完整的 Shot Specification 是可迁移的事实来源，Provider 请求则作为 Generation 快照留档。

## 9. MVP 范围

### 9.1 MVP 要验证的问题

> 一个没有影视和 Prompt 经验的用户，能否只通过描述想法和少量确认，在桌面端完成一支结构连贯、可预览、可导出的多镜头短片？

### 9.2 MVP 必须包含

1. 本地创建、打开、保存电影项目。
2. 从一句自然语言创建故事提案。
3. AI 自动拆解 Scene 和 Shot。
4. 用户可接受、自然语言修改或重新设计方案。
5. Scene / Shot 列表与基础编辑。
6. 首期 MiniMax 视频生成接入。
7. 生成任务状态、失败原因和重试。
8. 每个镜头保留多个生成版本并选择采用版本。
9. 生成结果自动进入基础时间线。
10. 电影预览与单一标准格式导出。
11. 普通模式默认隐藏 Prompt。
12. 导演模式提供核心高级字段。

### 9.3 MVP 暂不包含

- 多人实时协作和云端项目同步。
- 完整非线性专业剪辑能力。
- 复杂特效、调色和音频混音台。
- 模型市场和自动跨供应商择优。
- 数字人训练、动作捕捉和 3D 场景编辑。
- 长篇电影的一键全自动生成。
- 移动端与 Web 端。

### 9.4 建议首期约束

- 成片目标：15–60 秒。
- 项目规模：1–5 个场景，3–12 个镜头。
- 时间线：单主视频轨，加基础音频轨。
- 导出：先支持一个稳定的通用格式与固定预设。
- 生成策略：默认逐镜头确认和生成，允许批量提交但明确成本。

## 10. 关键页面

### 10.1 创作首页

目标：让用户立即表达想法，并快速回到正在制作的电影。

核心元素：品牌标题、创作输入框、开始创作按钮、灵感示例、最近电影。

### 10.2 AI 提案页

目标：确认 AI 是否正确理解用户，而不是立即消耗生成额度。

核心元素：意图复述、故事梗概、风格与时长建议、场景和镜头概览、接受/修改/重新设计。

### 10.3 电影工作台

目标：完成从结构设计、镜头生成到粗剪预览的主要工作。

核心元素：项目树、镜头画布、播放器、AI 导演对话、任务状态、时间线。

### 10.4 镜头检查器

普通模式显示：镜头画面、主体动作、情绪、时长、参考图、生成和改写操作。

导演模式增加：摄影机、焦段、运镜、构图、灯光、Prompt、Negative Prompt、Seed、Provider 和 Model。

### 10.5 导出页

目标：用尽可能少的配置获得可分享文件。

核心元素：完整预览、缺失镜头检查、分辨率/画幅预设、输出位置、导出进度和结果入口。

## 11. 关键交互与状态

### 11.1 可撤销的 AI 修改

AI 对故事、场景和镜头的修改必须在应用前展示影响范围；应用后可以撤销。重新设计默认创建候选版本，不直接覆盖用户已确认内容。

### 11.2 生成不是黑盒

每个镜头明确展示等待、提交、生成、成功、失败或取消状态。失败时提供可理解的原因和下一步操作，而不只显示供应商错误码。

### 11.3 成本确认

任何可能产生费用的生成或重新生成操作，都应在提交前说明镜头数量和预计消耗；批量操作需要二次确认。

### 11.4 本地数据安全

项目编辑自动保存。媒体文件、项目描述文件、缩略图与缓存应有明确边界；移动或删除源文件时给出影响提示。

## 12. 非功能要求

- **可恢复性**：应用异常退出后能够恢复最近项目与未完成任务信息。
- **可迁移性**：核心项目数据不绑定单个 Provider。
- **一致性**：角色、场景和视觉风格能够作为镜头间共享约束。
- **可观察性**：生成请求具备任务状态、耗时、错误和重试记录。
- **隐私**：清晰提示哪些内容会发送至云端模型服务。
- **性能**：长耗时生成不阻塞本地编辑和其他镜头操作。
- **无障碍**：核心操作支持键盘，状态不只依赖颜色表达。

## 13. 成功指标

### 13.1 北极星指标

**成功导出电影的创作用户占比。**

它同时衡量产品是否帮助用户跨越构思、分镜、生成和剪辑的完整链路，而不仅是产生了多少视频片段。

### 13.2 MVP 观察指标

- 从首次输入到接受分镜方案的完成率。
- 从创建项目到首次生成成功的时间。
- 创建项目后成功生成至少 3 个镜头的用户占比。
- 生成成功率与失败后重试成功率。
- 镜头重新生成次数与采用率。
- 粗剪预览率和最终导出率。
- 普通模式与导演模式的使用比例。

## 14. 产品语言规范

产品语言应围绕创作结果和导演动作，不围绕技术实现。

| 避免使用 | 推荐使用 |
| --- | --- |
| Create Project | 开始创作电影 |
| Submit Prompt | 生成这个镜头 |
| Task / Job | 生成任务 |
| Output | 镜头素材 / 成片 |
| Parameters | 镜头设置 |
| AI Agent | AI 导演助手 |
| API Error | 生成失败，并给出可行动原因 |

语气应像专业、克制、尊重创作权的幕后伙伴。避免宣称 AI 是导演；AI 可以提供导演建议，但最终决定权和“导演”身份属于用户。

## 16. 后续待定事项

以下决策在进入交互设计和技术方案前需要进一步确认：

1. 产品正式中文名、英文名及应用内简称。
2. 首期目标平台：Windows、macOS，或同时支持。
3. MiniMax 具体模型、可用输入形式、时长和分辨率限制。
4. AI 编剧与 Director Engine 使用的模型与结构化输出协议。
5. 用户自备 API Key 还是产品统一计费。
6. 首期是否包含旁白、对白、配乐和环境音生成。
